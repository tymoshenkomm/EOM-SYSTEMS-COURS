> **Мета роботи:** Експериментально дослідити шлях перетворення високорівневого коду C у машинні інструкції процесора, навчитися читати базовий Assembly (Intel syntax), співвідносити керуючі конструкції з низькорівневими командами та оцінювати вплив оптимізації компілятора.

```text
C source code ──▶ Compiler (GCC) ──▶ Assembly (.s) ──▶ Assembler ──▶ Machine Code (bytes) ──▶ CPU
```

## 1. Завдання 1 — Отримання Assembly (`arithmetic.c`)

- **Які операції виконує CPU для `int result = a + b;`:** Процесор виділяє місце на стеку для змінних `a` (5) та `b` (7), завантажує їх з пам'яті у регістри (`eax`, `edx`), виконує додавання в АЛП і записує результат (`12`) назад у комірку пам'яті змінної `result`.
- **Чи кожному рядку C відповідає рівно одна Assembly-інструкція?** Ні, одному рядку C зазвичай відповідає кілька машинних інструкцій.
- **Чи бачите ви в Assembly змінні з назвами `a`, `b`, `result`?** Ні, імен змінних на рівні Assembly вже немає — замість них використовуються адреси відносно стеку (`[rbp-4]`, `[rbp-8]`, `[rbp-12]`) та регістри.
- **Скільки інструкцій приблизно відповідає тілу `main()`?** Близько **12–15 інструкцій**.
- **Чи присутня операція додавання?** Так, інструкція `add eax, edx`.

## 2. Завдання 2 — Арифметичні операції (`operations.c`)

| Операція в C | Основна Assembly-інструкція | Опис дії процесора |
| :---: | :--- | :--- |
| `a + b` | `add eax, edx` | Додавання двох 32-бітних регістрів |
| `a - b` | `sub eax, edx` | Віднімання значення `edx` від `eax` |
| `a * b` | `imul eax, DWORD PTR -8[rbp]` | Знакове множення `eax` на значення зі стеку |

> **Пояснення:** При зміні знака операції в C структура функції (пролог, передача параметрів через `edi` та `esi`, повернення через `eax`) залишається незмінною — змінюється лише сама інструкція АЛП.

## 3. Завдання 3 — Умовний оператор `if / else` (`condition.c`)

| Конструкція C | Інструкції Assembly (Intel) | Логіка виконання |
| :--- | :--- | :--- |
| `if (a > b)` | `cmp eax, DWORD PTR -8[rbp]` / `jle .L2` | Порівняння `a` і `b`; якщо `a <= b`, стрибок на мітку `.L2` |
| `return a;` | `mov eax, DWORD PTR -4[rbp]` / `jmp .L3` | Запис `a` у регістр результату `eax` і перехід у кінець функції |
| `else` | `.L2:` | Мітка початку альтернативної гілки |
| `return b;` | `mov eax, DWORD PTR -8[rbp]` | Запис `b` у регістр результату `eax` |

> **Чи існує машинна інструкція `IF`?** Ні. CPU виконує порівняння `cmp` (виставляє прапорці в `RFLAGS`), а потім інструкція умовного переходу `jle` (*jump if less or equal*) змінює потік виконання залежно від цих прапорців.

## 4. Завдання 4 — Цикл `for` (`loop.c`)

```text
initialization (i = 1) ──▶ jmp .L2 (condition: i <= n) ──▶ [true: jle .L3] ──▶ body (sum += i) ──▶ increment (i++) ──┐
                                        ▲                                                                             │
                                        └─────────────────────────────────────────────────────────────────────────────┘
```

- **Інструкція порівняння:** `cmp eax, DWORD PTR -20[rbp]` (порівнює лічильник `i` зі значенням `n`).
- **Інструкції переходу:** Безумовний стрибок `jmp .L2` на перевірку умови та умовний перехід `jle .L3` назад на початок тіла циклу.
- **Чи існує в Assembly поняття `for`?** Ні, цикли реалізуються за допомогою міток, лічильників, `cmp` та переходів `jmp` / `jle`.
- **Як CPU визначає, що цикл потрібно повторити?** Після збільшення `i` (`add DWORD PTR -4[rbp], 1`) виконується `cmp`, і якщо прапорці `RFLAGS` підтверджують `i <= n`, інструкція `jle .L3` повертає `RIP` на початок тіла циклу.

## 5. Завдання 5, 6 та 7 — Виклик функції та Machine Code (`operations.c`)

- **Механізм `call` та `ret`:** Перед викликом `calculate(10, 20)` аргументи кладуться у регістри `esi` (`20`) та `edi` (`10`), після чого виконується `call calculate`. Інструкція `call` автоматично зберігає адресу повернення у стек, щоб `ret` знав, куди повернутися після завершення функції. Результат повертається у регістрі `eax`.

### Реальний Machine Code (`objdump -d -M intel operations`)

| Address | Machine-code bytes | Assembly |
| :--- | :--- | :--- |
| `0x1191` | `48 89 c7` | `mov rdi, rax` |
| `0x1194` | `b8 00 00 00 00` | `mov eax, 0x0` |
| `0x1199` | `e8 b2 fe ff ff` | `call 1050 <printf@plt>` |

- **Що зберігається у виконуваному файлі?** Виключно двійковий **machine code**, а `objdump` дизасемблює байти у текст Assembly для зручності людини.
- **Чи мають інструкції x86-64 однакову довжину?** Ні, довжина змінна (`mov rdi, rax` — 3 байти, `mov eax, 0x0` та `call` — по 5 байтів).

## 6. Завдання 8 та 9 — Оптимізація `-O0` vs `-O2` (`optimize.c`)

| Режим компіляції | Поведінка компілятора GCC |
| :--- | :--- |
| **`-O0`** *(без оптимізації)* | Зберігає змінні на стеку, чесно викликає `answer()` через `call`, виконує додавання `10 + 20`. |
| **`-O2`** *(з оптимізацією)* | Застосовує *inlining* та *constant folding*: повністю прибирає виклик функції і записує готове число `30` (`mov eax, 30`). |

> **Експеримент `optimize.c`:** Спрацював **Варіант B** (одразу повертається `30`). Згідно з правилом *«as-if»* у стандарті C, компілятор має право на спрощення, якщо зовнішня поведінка програми не змінюється.

## 8. Відповіді на контрольні питання

<details>
<summary><b>Натисніть, щоб розгорнути відповіді на всі 16 контрольних питань</b></summary>

1. **Що таке ISA?** *Instruction Set Architecture* (архітектура набору інструкцій) — специфікація, що визначає набір машинних команд, регістрів, типів даних і режимів адресації процесора (наприклад, x86-64 або ARM).
2. **Чому CPU не може безпосередньо виконувати C-код?** Процесор виконує лише двійкові машинні інструкції, тоді як C є високорівневою текстовою абстракцією для програміста.
3. **У чому різниця між Assembly та machine code?** *Machine code* — це реальні байти інструкцій у пам'яті/файлі, а *Assembly* — їхнє текстове представлення (мнемоніки `mov`, `add` тощо).
4. **Що робить параметр GCC `-S`?** Зупиняє компіляцію після етапу генерації Assembly-коду та зберігає результат у текстовий `.s` файл.
5. **Навіщо ми використовували `-O0`?** Щоб вимкнути оптимізації та побачити пряму, незмінену відповідність між кожним рядком C і машинними інструкціями.
6. **Що таке operand?** Це дані або місце їхнього розташування (регістр, адреса в пам'яті чи константа), над якими інструкція виконує дію.
7. **Для чого використовується `mov`?** Для копіювання даних між регістрами, пам'яттю (стеком) та завантаження констант.
8. **Яку роль виконує `cmp`?** Порівнює два операнди шляхом віднімання (без збереження результату) і встановлює прапорці стану в регістрі `RFLAGS`.
9. **Як на машинному рівні реалізується `if`?** Через комбінацію порівняння `cmp` та умовного переходу (`jle`, `jg`, `je`, `jne`), що перевіряє прапорці `RFLAGS`.
10. **Як реалізується цикл?** Через мітки, лічильник, порівняння `cmp` та інструкцію переходу (`jmp` / `jle`), яка повертає виконання на початок тіла циклу.
11. **Для чого потрібна інструкція `call`?** Зберігає адресу наступної інструкції у стек і передає керування на першу інструкцію викликаної функції.
12. **Для чого потрібна `ret`?** Витягує зі стеку адресу повернення і передає туди керування для продовження основної програми.
13. **Чому одному рядку C не обов'язково відповідає одна машинна інструкція?** Одна високорівнева дія (наприклад, `sum += i`) потребує кількох базових кроків CPU: читання з пам'яті, обчислення в регістрі та запису назад.
14. **Що показує `objdump -d`?** Дизасемблює виконуваний файл, відображаючи адреси інструкцій, реальні шістнадцяткові байти машинного коду та відповідні інструкції Assembly.
15. **Чому Assembly, отриманий з `-O0` та `-O2`, може суттєво відрізнятися?** При `-O2` компілятор оптимізує швидкість і розмір: відмовляється від зайвого стеку на користь регістрів, вбудовує функції (*inlining*) та наперед обчислює константи.
16. **Чи може компілятор повністю видалити частину написаного програмістом C-коду? За яких умов?** Так (*dead code elimination*), якщо код є недосяжним, його результат ніде не використовується або він не створює жодних спостережуваних побічних ефектів.

</details>

## 9. Висновок

Під час виконання лабораторної роботи було досліджено шлях перетворення програми мовою C у машинні інструкції. Експериментально підтверджено, що процесор не оперує іменами змінних чи високорівневими конструкціями `if` і `for`, а працює виключно з регістрами, адресами стеку, прапорцями стану (`cmp`) та переходами (`jmp`, `jle`, `call`, `ret`), тоді як оптимізатор GCC суттєво спрощує машинний код без зміни логіки програми.
