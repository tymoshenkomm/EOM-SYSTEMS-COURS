# Лабораторна робота №1. Представлення даних у пам'яті

## Завдання 1. Розміри типів даних (`types.c`)

| Тип | Розмір (bytes) | Розмір (bits) |
| :--- | :---: | :---: |
| `char` | 1 | 8 |
| `short` | 2 | 16 |
| `int` | 4 | 32 |
| `long` | 8 | 64 |
| `long long` | 8 | 64 |
| `float` | 4 | 32 |
| `double` | 8 | 64 |
| `void *` | 8 | 64 |

**Відповіді:**
1. **Чи всі типи займають однакову кількість пам'яті?** Ні, кожен тип займає різну кількість байтів (від 1 до 8) залежно від того, які числа або дані він зберігає.
2. **Скільки бітів займає `int` у вашому середовищі?** 32 біти (це 4 байти).
3. **Який розмір має вказівник `void *`?** 8 байтів, або 64 біти.
4. **Що розмір вказівника говорить вам про архітектуру середовища?** Оскільки вказівник зберігає адресу в пам'яті і займає 64 біти, система працює на 64-бітній архітектурі (`x86_64`).

## Завдання 2. Decimal → Hexadecimal (`representations.c`)

| Decimal | Hexadecimal | Binary |
| :---: | :---: | :---: |
| 10 | `0xA` | `00001010` |
| 65 | `0x41` | `01000001` |
| 127 | `0x7F` | `01111111` |
| 255 | `0xFF` | `11111111` |
| 256 | `0x100` | `00000001 00000000` |
| 1024 | `0x400` | `00000100 00000000` |

**Чому `65`, `0x41` та `01000001` можуть представляти одне й те саме числове значення?**  
У пам'яті лежить одне й те саме двійкове число `01000001`. А `65` і `0x41` — це просто різні способи записати його на екрані (у десятковій та шістнадцятковій системах), щоб нам було зручніше читати.

## Завдання 3. Виведення бітів (`binary.c`)

**Чому функція починає перевірку з біта 7, а не з біта 0?**  
Ми читаємо числа зліва направо — від найбільшого розряду до найменшого. Біт 7 найстарший (це 128), а біт 0 наймолодший (одиниця). Якщо почати з 0, число виведеться задом наперед.

## Завдання 4. Символ — це також число (`characters.c`)

| Character | Decimal | Hex |
| :---: | :---: | :---: |
| `A` | 65 | `0x41` |
| `B` | 66 | `0x42` |
| `a` | 97 | `0x61` |
| `0` | 48 | `0x30` |
| `9` | 57 | `0x39` |

**Що фактично зберігається у змінній `char c = 'A';`?**  
У змінній лежить звичайне число `65` (код літери `A` в таблиці ASCII). Сама літера з'являється вже при виводі в консоль, коли `printf` бачить `%c` і підставляє потрібний символ за цим кодом.

## Завдання 5. Signed та Unsigned (`signed_unsigned.c`)

**Як можливо, що `11111111` може означати `255` і водночас `-1`? Що визначає значення цієї послідовності бітів?**  
Усе залежить від типу даних, який ми вказали в коді. Для беззнакового `uint8_t` усі біти додатні, тому їхня сума дає `255`. А для знакового `int8_t` працює доповняльний код (*two's complement*): перший біт відповідає за мінус (`-128`), і разом із рештою одиниць (`+127`) виходить `-1`.

## Завдання 6. Дослідження межі unsigned integer (`overflow.c`)

**Поясніть результат `255 + 1 = 0` через кількість доступних бітів.**  
У типі `uint8_t` є рівно 8 бітів, і число `255` (`11111111`) забиває їх повністю. Коли додаємо `1`, одиниця переноситься в 9-й розряд (`1 00000000`), але місця під 9-й біт немає — він просто відкидається, і в змінній залишаються самі нулі (`0`).

## Завдання 7 та 8. Пам'ять та визначення Endianness (`memory.c`)

**Відповіді:**
1. **Порядок байтів системи:** `Little-endian`.
2. **У якому напрямку змінюються адреси?** Адреси йдуть на збільшення (кожен наступний байт має адресу на 1 більшу).
3. **Який байт знаходиться за найменшою адресою?** Наймолодший байт — `0x78`.
4. **Чому це свідчить про little-endian?** У *Little-endian* число записується в пам'ять «з хвоста» — молодший байт кладеться першим за найменшою адресою.
5. **Чи змінилося саме число `0x12345678`?** Ні, саме число залишилося таким же, змінився тільки порядок, у якому його байти розкладені по комірках пам'яті.

## Завдання 9. Один набір бітів — різні інтерпретації

| Інтерпретація | Значення |
| :--- | :--- |
| Binary | `01000001` |
| Hexadecimal | `0x41` |
| Unsigned decimal | `65` |
| ASCII character | `'A'` |

**Чому комп'ютеру недостатньо знати лише біти, щоб визначити значення даних?**  
Самі по собі нулі та одиниці в пам'яті нічого не означають. Щоб програма розуміла, що з ними робити, їй потрібен **контекст**, який ми задаємо через **тип даних**. Саме тип підказує, як **інтерпретувати** цей набір бітів: рахувати його як число, вивести як літеру чи прочитати як адресу.
